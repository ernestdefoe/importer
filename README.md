# Importer / Converter for Flarum 2

Migrate an existing forum into **Flarum 2** — from **phpBB, vBulletin (3/4/5), XenForo, MyBB, SMF, Vanilla, NodeBB, Invision, Discourse, Web Wiz Forums**, or **Convoro**. Everything is driven from the **admin panel**: pick a platform, connect to its database (or upload a dump), test it, then run the import in **small batches with a live progress bar** — so even a large forum won't time out.

> Ported from the Convoro importer suite. Members keep their passwords where possible (bcrypt hashes are copied straight across; other formats are randomised so the member simply resets on first login). Post bodies are converted to Flarum's native rich-text format, so BBCode / HTML / Markdown comes across as real formatting — bold, italics, links, quotes, lists and code.

## Runs on shared hosting

No queue worker and no SSH required. The import runs as a loop of **small "step" requests straight from your browser**, each processing one bounded batch and returning — so it can never hit a web timeout. Progress and the source→Flarum id-maps are persisted in the database, so if the tab is closed or the connection drops, reopen the page and it **resumes exactly where it left off**. If you *do* have a queue worker (e.g. `fof/redis`), the import is handed to it and runs fully in the background instead — either way it's safe.

## The admin area

The whole tool lives on the extension's settings page.

### 1. The wizard

Pick a **source platform**, then either **connect to a database** (host, port, database name, username, password, and table prefix) or **upload a database file** (a `mysqldump` `.sql`/`.sql.gz`, or a SQLite file) for hosts that only hand you a dump. Nothing is written until you start.

![Importer admin — connection wizard](screenshots/admin-1-initial.png)

### 2. Test the connection

**Test connection** validates the credentials, confirms it really is the platform you picked, then reports exactly what it found — here **21 Users, 4 Categories, 30 Topics, 371 Posts** — so you know it will pull the right data before committing. **Start import** only lights up once the test passes.

![Importer admin — successful connection test with row counts](screenshots/admin-2-tested.png)

### 3. Watch it run

**Start import** kicks off the batched run and shows a **live progress bar** with the current phase and running totals — categories, members, topics and posts — updating as it goes.

![Importer admin — live progress bar with running totals](screenshots/admin-3-progress.png)

When it finishes you get a summary of everything imported, and can start another.

![Importer admin — completed import summary](screenshots/admin-3-complete.png)

## Supported sources

| Platform | Notes |
|----------|-------|
| phpBB 3.x | BBCode posts; bcrypt passwords copied across |
| vBulletin 3 / 4 · vBulletin 5 / 6 | one option covers both — vB5's node schema is auto-detected |
| XenForo 1.x / 2.x | BBCode posts; XF2 bcrypt passwords copied |
| MyBB 1.8 · SMF 2.0 / 2.1 | BBCode posts |
| Vanilla · NodeBB | Markdown / mixed formats; NodeBB reads its Redis store (needs the `redis` PHP extension) |
| Invision Community (IP.Board) | HTML posts, quotes & mentions cleaned up |
| Discourse | PostgreSQL source (needs `pdo_pgsql`) |
| Web Wiz Forums | Microsoft SQL Server source. Connect directly where the host has `pdo_sqlsrv`, or **upload a script** generated by SSMS (*Generate Scripts → schema and data*) on any host |
| Convoro | Convoro → Flarum; bcrypt passwords copied, so members keep their logins |

Categories are imported as **tags** (requires `flarum/tags`); if tags aren't installed, discussions and posts still import, just untagged.

## How it works

- **Timeout-proof** — the run is a resumable state machine; each request processes one small batch and returns, so memory stays flat and nothing runs long enough to time out. Works with or without a queue worker.
- **Resumable** — progress, cursors and the source→Flarum id-maps live in the database, so a run survives a closed tab, a reload, or a dropped connection.
- **Faithful content** — post bodies go source → HTML/Markdown → Flarum's formatter, landing in Flarum's native stored format so they render as proper rich text.
- **Relations preserved** — members, tags, discussions, first/last-post pointers, comment counts and participant counts are all rebuilt.

## Private messages

Private messages come across too, into Flarum's own **Messages** (`flarum/messages`, bundled with Flarum 2). They are on by default whenever Messages is enabled. Switch **Bring private messages across** off in the wizard, or pass `--no-private-messages` on the command line, to leave them behind. If Messages is not enabled, the import says so in its summary and moves on.

| Platform | Where they come from |
|----------|----------------------|
| phpBB 3.x | `privmsgs` + `privmsgs_to` |
| vBulletin 3 / 4 | `pmtext` + `pm` |
| vBulletin 5 / 6 | `privatemessage` nodes + `sentto` (system notifications and requests are left out) |
| XenForo 1.x / 2.x | `xf_conversation_master` + `xf_conversation_message` + `xf_conversation_recipient` |
| MyBB 1.8 | `privatemessages` (each member's copies are recognised as one message; drafts are left out) |
| SMF 2.0 / 2.1 | `personal_messages` + `pm_recipients` |
| Invision Community | `core_message_topics` + `core_message_posts` + `core_message_topic_user_map` (drafts are left out) |
| Discourse | personal-message topics, with `topic_allowed_users` and the members of `topic_allowed_groups` (messages the system sent itself, whispers and deleted posts are left out) |
| NodeBB | chat rooms and their messages (NodeBB 3's public chat channels are not private, so they are left out) |
| Vanilla | `Conversation` + `ConversationMessage` + `UserConversation` |
| Web Wiz Forums | `tblPMMessage` |
| Convoro | the messenger (Convoro 1.x and 2) |

How they land:

- **Two people:** the conversation between those two members in Messages, with every message in order and its original author and date. Flarum keeps one conversation per pair of members, so every old thread between the same two people ends up in it, in date order. Text is converted exactly as posts are. Flarum's direct messages have no titles, so old subjects are not kept for them.
- **Three or more people:** a group conversation, named after the old subject, when [Group Messages](https://github.com/ernestdefoe/group-messages) is installed and enabled. Without it they are **skipped and counted**: the summary says how many. They are never split into separate two-person conversations, because that would show people messages that were addressed to others as well. Install Group Messages later and run a sync: the skipped ones come across then.
- **Blind copies** (phpBB, vBulletin, MyBB, SMF): a member who was blind-copied gets the message in their own conversation with the sender, so the other recipients never see that they had it.
- **Deleted messages:** a message that every participant deleted is not imported, and nor is a draft. Messages has no way to hide one conversation from one member, so the closest thing is used instead: a member who deleted their copies of a conversation, or left it, is not added to it here. A member who kept any part of a two-person conversation sees all of it, because that is how Flarum shows a conversation.
- **Deleted accounts:** messages from members who were not imported show as written by a deleted member, exactly as their posts do. A deleted account is never added as a member.
- **Read and unread:** where the old forum recorded it, a message somebody had not read yet arrives unread for them. Everything else arrives read, so a whole history does not land as unread.
- **Privacy:** only the people in a conversation can see it. Nothing else on the forum shows it, and the import never logs or reports what a message says, only counts. Members are not notified when old messages arrive.

**Already imported before this version?** Run a sync and the messages come across: all of them the first time, then only new ones after that. A message is never brought across twice.

```bash
php flarum importer:run --sync --dry-run --password=secret   # counts them, saves nothing
php flarum importer:run --sync --password=secret
```

Or use **Sync new content** in the admin. For Vanilla, NodeBB and vBulletin 5, whose other content cannot be synced yet, a sync brings across the private messages only.

## Keeping the old forum in sync

Import once, then keep the old forum running while you set Flarum up, and sync as often as you like before you switch over. A sync copies only what the old forum has gained since the last run:

- **new members, categories, discussions, replies and private messages** — a reply in an old topic lands in the discussion that topic became, numbered after whatever is there now (including replies written on Flarum);
- **edits** made on the old forum, for phpBB, XenForo, MyBB, SMF and Invision (they record an edit time). An edit is only copied over a post nobody has edited on Flarum — if somebody has, the Flarum edit wins and the sync counts it as kept;
- the **counters** of whatever it touched: discussion reply counts and last posts, member post counts, tag counts. The old-link redirects pick up the new discussions on their own.

Nothing written on Flarum is changed or removed, and nothing deleted on the old forum is deleted here. Run it as many times as you like: what is already here is never copied twice.

**In the admin:** Admin → Importer shows **Keep the old forum in sync** once an import has finished (also on the finished-import screen). Click **Sync new content**, enter the old database's password again (it is never stored after a run), and click **Sync now**. An import made with 0.3.7 or earlier kept no connection settings, so the first time you fill in the same details as the import.

**From the command line:**

```bash
php flarum importer:run --sync --password=secret             # reuses the last import's settings
php flarum importer:run --sync --dry-run --password=secret   # counts what would come across, saves nothing
# an import made with 0.3.7 or earlier: give the connection once, as for the import
php flarum importer:run --sync --host=127.0.0.1 --database=my_old_forum --username=root --password=secret --prefix=phpbb_
```

Good to know:

- A sync reads only what is past the last thing it imported (plus a few hundred ids back, for posts and topics approved late), so it is quick. The **first** sync of an import made with 0.3.7 or earlier reads every post once, to learn which ones are already here.
- Only one import or sync runs at a time.
- Not yet for Vanilla, NodeBB or vBulletin 5, apart from their private messages (vBulletin 3/4 syncs new content, without edits; so do Discourse, Convoro and Web Wiz). Changes to members, titles or categories on the old forum, and deletions, are not synced.

## Requirements & tips

- Import into a **fresh Flarum** for the cleanest result.
- A queue worker is **optional** — the import runs from the browser without one. If you have `fof/redis` + a worker, it runs in the background instead.
- There's also a CLI for very large migrations or scripting:

```bash
php flarum importer:run --source=phpbb \
  --host=127.0.0.1 --database=my_old_forum --username=root --password=secret --prefix=phpbb_
# add --test to only check the connection and show counts
```

- Imported with 0.3.6 or earlier and see `<!-- m --><a class="postlink" …>` in old phpBB posts, or `&amp;` / `&lt;` where `&` and `<` should be? Repair them in place — the old board is not needed:

```bash
php flarum importer:repair-text --dry-run   # counts + a preview, saves nothing
php flarum importer:repair-text             # chunked, safe to run twice
# add --all if the import was reset in the wizard (only phpBB 3.0 markup is repaired then)
```
